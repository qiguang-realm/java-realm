在 Java Spring 中，使用 @Transactional(rollbackFor = Exception.class) 的方法如果内部通过 try-catch 捕获了异常，必须确保异常被重新抛出或手动标记事务回滚，否则事务不会生效。
以下是具体解决方案：

1. 手动标记事务回滚（推荐）
在 catch 块中直接调用 TransactionAspectSupport.currentTransactionStatus().setRollbackOnly()，强制标记事务为回滚状态，无需重新抛出异常。


import org.springframework.transaction.annotation.Transactional;
import org.springframework.transaction.interceptor.TransactionAspectSupport;

@Transactional(rollbackFor = Exception.class)
public void yourMethod() {
    try {
        // 业务代码（可能抛出异常的操作）
    } catch (Exception e) {
        // 捕获异常后，手动标记事务回滚
        TransactionAspectSupport.currentTransactionStatus().setRollbackOnly();
        // 可选：记录日志或其他处理
    }
}


2. 重新抛出异常
在 catch 块中将异常重新抛出（或包装为 RuntimeException），让事务管理器捕获到异常并触发回滚。


@Transactional(rollbackFor = Exception.class)
public void yourMethod() throws Exception {
    try {
        // 业务代码（可能抛出异常的操作）
    } catch (Exception e) {
        // 可选：记录日志或其他处理
        throw e; // 重新抛出异常，事务会回滚
    }
}



关键注意事项

1.事务代理机制
Spring 事务基于 AOP 代理实现。如果异常被 try-catch 后未重新抛出或手动标记回滚，代理类无法感知异常，导致事务提交。

2.异常类型匹配
rollbackFor = Exception.class 确保所有 Exception（包括检查型异常）触发回滚，但需确保异常未被“吞噬”。

3.自调用问题
如果方法通过类内部调用（如 this.yourMethod()），事务注解会失效。需通过代理对象调用（如注入自身 Bean）。

4.事务传播行为
检查事务的传播行为（propagation）是否符合预期，例如 REQUIRED 或 REQUIRES_NEW。


完整示例


@Service
public class YourService {

    @Resource
    private SomeRepository repository;

    @Transactional(rollbackFor = Exception.class)
    public void transactionalMethod() {
        try {
            // 数据库操作 1
            repository.save(entity1);
            // 数据库操作 2（可能抛出异常）
            repository.update(entity2);
        } catch (Exception e) {
            // 记录日志
            logger.error("操作失败", e);
            // 手动标记回滚
            TransactionAspectSupport.currentTransactionStatus().setRollbackOnly();
        }
    }
}


在 Spring 事务管理中，如果每个数据库操作（如 save 和 update）内部都通过 try-catch 捕获了异常且未重新抛出或标记回滚，事务将无法正确回滚，
因为这些异常会被“吞噬”，外层事务方法无法感知到异常的发生。以下是具体分析和解决方案：


1. 问题分析：事务失效的场景
假设 repository.save(entity1) 和 repository.update(entity2) 的代码结构如下：

public class SomeRepository {
    public void save(Entity entity) {
        try {
            // 数据库操作（可能抛异常）
        } catch (Exception e) {
            // 捕获异常但未重新抛出或标记回滚
            logger.error("保存失败", e);
        }
    }

    public void update(Entity entity) {
        try {
            // 数据库操作（可能抛异常）
        } catch (Exception e) {
            // 捕获异常但未重新抛出或标记回滚
            logger.error("更新失败", e);
        }
    }
}

此时：

即使 save 或 update 内部发生异常，异常也会被内部的 try-catch 捕获并“吞噬”，不会传播到外层事务方法。

外层事务方法（如 @Transactional 注解的方法）感知不到任何异常，事务会正常提交，导致数据不一致。


2. 解决方案：确保异常传播或手动回滚
要让事务正确回滚，必须确保异常能被外层事务方法感知或主动标记回滚。以下是具体方法：

方法 1：内部方法重新抛出异常（推荐）
修改 save 和 update 方法，确保异常被重新抛出（或包装为 RuntimeException）：


public class SomeRepository {
    public void save(Entity entity) {
        try {
            // 数据库操作（可能抛异常）
        } catch (Exception e) {
            logger.error("保存失败", e);
            throw new RuntimeException(e); // 包装为运行时异常抛出
        }
    }

    public void update(Entity entity) {
        try {
            // 数据库操作（可能抛异常）
        } catch (Exception e) {
            logger.error("更新失败", e);
            throw e; // 直接抛出原异常（需声明 throws）
        }
    }
}


关键点：

如果抛出检查型异常（如 SQLException），需在方法签名中声明 throws。

使用 @Transactional(rollbackFor = Exception.class) 确保所有异常触发回滚。

方法 2：内部方法手动标记事务回滚
如果无法修改内部方法的异常抛出逻辑（如使用第三方库），可在内部方法中直接标记事务回滚：


import org.springframework.transaction.interceptor.TransactionAspectSupport;

public class SomeRepository {
    public void save(Entity entity) {
        try {
            // 数据库操作（可能抛异常）
        } catch (Exception e) {
            logger.error("保存失败", e);
            // 手动标记事务回滚
            TransactionAspectSupport.currentTransactionStatus().setRollbackOnly();
        }
    }
}


注意：

此方法需确保 save 或 update 方法本身处于事务上下文中（例如被 @Transactional 方法调用）。

如果内部方法不在事务上下文中，setRollbackOnly() 会抛出异常。

3. 事务边界与异常传递机制
事务边界：Spring 事务的边界由 @Transactional 注解标记的方法定义。只有在此边界内抛出的异常才会触发回滚。

异常传递：如果内部方法捕获异常后未重新抛出，异常不会传递到事务边界，事务无法感知异常。

代理机制：Spring 事务基于代理实现，内部方法调用（如 this.save()）可能导致事务失效，需通过代理对象调用（如注入自身 Bean）。

4. 完整示例修正
确保内部方法异常传递到事务边界：

@Service
public class YourService {

    @Resource
    private SomeRepository repository;

    @Transactional(rollbackFor = Exception.class)
    public void transactionalMethod() {
        try {
            repository.save(entity1); // 内部方法抛出异常
            repository.update(entity2); // 内部方法抛出异常
        } catch (Exception e) {
            // 手动标记回滚（可选，因异常已传播到事务边界）
            TransactionAspectSupport.currentTransactionStatus().setRollbackOnly();
            throw e; // 重新抛出以确保事务回滚
        }
    }
}


总结
核心原则：确保异常传递到事务边界，或在事务上下文中手动标记回滚。

内部方法设计：避免在数据库操作内部“吞噬”异常，除非明确需要忽略错误。

事务上下文：确保内部方法处于事务上下文中（如通过 @Transactional 传播机制）。

如果每个数据库操作内部都捕获了异常但不传播，事务将无法回滚。必须通过重新抛出异常或主动标记回滚，让事务管理器感知到异常状态。

标准的Java事务方法模板，使用Spring的@Transactional注解管理事务，包含try-catch异常处理、嵌套方法调用和多种场景处理

import org.springframework.transaction.annotation.Transactional;
import org.springframework.stereotype.Service;
import org.springframework.transaction.interceptor.TransactionAspectSupport;

@Service
public class BusinessService {

    // 核心事务方法
    @Transactional(
        rollbackFor = Exception.class,  // 指定所有异常都触发回滚
        propagation = Propagation.REQUIRED,  // 默认传播行为：支持当前事务，不存在则创建新事务
        isolation = Isolation.DEFAULT,      // 使用数据库默认隔离级别
        timeout = 30                        // 事务超时时间30秒
    )
    public void coreBusinessOperation(ParamObject param) {
        try {
            // 1. 数据校验（非数据库操作）
            validateParameters(param);

            // 2. 调用其他服务方法（同一事务内）
            EntityA entityA = createEntityA(param);
            EntityB entityB = createEntityB(param);

            // 3. 主业务逻辑
            processCoreBusiness(entityA, entityB);

            // 4. 调用外部方法（可能触发嵌套事务）
            callExternalService(entityA);

        } catch (BusinessException ex) {
            // 业务异常处理：记录日志并设置回滚标志
            log.error("Business error in transaction", ex);
            TransactionAspectSupport.currentTransactionStatus().setRollbackOnly();
            throw ex;  // 重新抛出异常让调用方感知

        } catch (Exception ex) {
            // 系统异常处理：记录日志并强制回滚
            log.error("System error in transaction", ex);
            TransactionAspectSupport.currentTransactionStatus().setRollbackOnly();
            throw new ServiceException("Transaction failed", ex);
        }
    }

    // --- 内部方法（属于同一事务） ---
    private void validateParameters(ParamObject param) {
        if (param == null) {
            throw new IllegalArgumentException("参数不能为空");
        }
        // 其他校验逻辑...
    }

    private EntityA createEntityA(ParamObject param) {
        EntityA entity = new EntityA();
        // 设置属性...
        return repositoryA.save(entity);  // 数据库操作1
    }

    private EntityB createEntityB(ParamObject param) {
        EntityB entity = new EntityB();
        // 设置属性...
        return repositoryB.save(entity);  // 数据库操作2
    }

    // --- 可能触发嵌套事务的方法 ---
    @Transactional(propagation = Propagation.REQUIRES_NEW)
    public void callExternalService(EntityA entity) {
        // 此方法将在新事务中执行
        externalService.process(entity);
    }

    // --- 主业务逻辑（包含多个数据库操作）---
    private void processCoreBusiness(EntityA a, EntityB b) {
        // 操作1：更新实体A
        a.setStatus(Status.PROCESSING);
        repositoryA.update(a);

        // 操作2：创建关联实体C
        EntityC c = new EntityC(a, b);
        repositoryC.save(c);

        // 操作3：批量处理
        processBatchItems(a.getItems());
    }

    // 批量处理方法
    private void processBatchItems(List<Item> items) {
        for (Item item : items) {
            processSingleItem(item);  // 循环处理每个项
        }
    }

    // 单条记录处理
    private void processSingleItem(Item item) {
        // 复杂处理逻辑...
        itemRepository.save(item);
    }
}

@Valid 和 @Validated 是 Java 中用于参数校验的核心注解，二者在功能定位和使用场景上有明显区别。以下是它们的对比详解：

一、核心区别对比表
特性	@Valid (JSR-303)	@Validated (Spring)
标准归属	Java EE 标准 (JSR-303/349/380)	Spring Framework 扩展
适用范围	方法参数/返回值、字段、构造器等	类、方法、参数
分组校验	不支持	支持
校验顺序控制	不支持	支持 @GroupSequence
级联校验	支持（需配合 @Valid）	需要显式声明
AOP 校验触发	不支持	支持（用于方法级别校验）
嵌套路径处理	自动处理嵌套对象	需手动指定 ValidationGroups

Controller 层参数校验（推荐 @Valid）：

@PostMapping("/users")
public ResponseEntity<?> createUser(
    @RequestBody @Valid UserDTO user) { // JSR-303 标准校验
    // ...
}

Service 层方法校验（需用 @Validated）：

@Service
@Validated // 启用方法级校验
public class UserService {
    public void updateUser(@Valid User user) { // Spring 扩展校验
        // ...
    }
}
