三张表关系分析如下：

表结构与关系
kyc_ad_space（广告位表）

主键：id
描述：广告位的基本信息，每个广告位有唯一 id。
kyc_ad_content（广告内容表）

主键：id
描述：广告内容的基本信息，每个广告内容有唯一 id。
kyc_ad_space_content（广告位与内容关联表）

主键：id
外键：space_id（关联广告位）、ad_id（关联广告内容）
描述：用于建立广告位与广告内容的多对多关系。一个广告位可以有多个广告内容，一个广告内容也可以被多个广告位使用。
逻辑关系
kyc_ad_space 通过 space_id 与 kyc_ad_space_content 关联。
kyc_ad_content 通过 ad_id 与 kyc_ad_space_content 关联。
kyc_ad_space_content 的唯一约束是 space_id, ad_id，确保一个广告位与一个广告内容的关联只出现一次。
业务操作主键选择建议
查询业务
如果查询广告位的详情或列表：以 kyc_ad_space.id 为主键。
如果查询广告内容详情或列表：以 kyc_ad_content.id 为主键。
如果查询某个广告位下有哪些广告内容：先用 kyc_ad_space.id，通过 kyc_ad_space_content 的 space_id 查询相关 ad_id，再查 kyc_ad_content。
如果查询某个广告内容属于哪些广告位：用 kyc_ad_content.id，通过 kyc_ad_space_content 的 ad_id 查询相关 space_id，再查 kyc_ad_space。
修改业务
修改广告位信息：用 kyc_ad_space.id。
修改广告内容信息：用 kyc_ad_content.id。
修改广告位与内容的关联：用 kyc_ad_space_content.id，或通过 space_id 和 ad_id 唯一约束定位到具体关联记录。
业务逻辑主键选择总结
单表操作（如详情、编辑、删除）：以该表的主键 id 为准。
关联操作（如广告位内的广告内容排序、广告内容分配到广告位）：以 kyc_ad_space_content 的主键 id 或唯一约束 space_id, ad_id 为准。
推荐业务主键操作原则
单表操作：主表主键 id
关联操作：关联表主键 id，或 space_id, ad_id 唯一约束
最佳实践：

关联查询、批量操作时，优先用主表的主键 id，通过关联表的外键（space_id 或 ad_id）进行操作。
如果是对关联本身（如激活/禁用某关系）进行操作，则以 kyc_ad_space_content.id 为准。
查询时一般以主表主键为入口，通过关联表连接另一主表。
简洁答案：

业务操作应以主表（kyc_ad_space 或 kyc_ad_content）的主键 id 为准，进行查询与修改；但如需操作广告位与广告内容的关系（如分配、移除、排序），则应以 kyc_ad_space_content 表的主键 id 或唯一约束（space_id, ad_id）为准。
